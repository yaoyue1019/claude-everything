# 架构设计（ADS）

基于 SRS 与现有技术栈生成 `docs/ADS.md`：

1. 2~3 个候选方案对比优劣、风险、依赖，并给出推荐与理由。
2. 总体架构：分层/组件划分、各模块职责与边界；模块较多时补组件图。
3. 技术选型逐条对应 SRS 关键约束（性能/安全/扩展性）。
4. 跨模块、含异步或分支较多的关键流程补时序图/活动图。
5. 与现有系统的集成方式、部署视图；部署结构复杂时补部署图。

## 要求

- 设计决策标注对应 SRS 需求编号；先了解现有代码与依赖再设计，保证集成可行。

## 约束

- 不确定的版本、兼容性、性能结论标「待确认」，禁止臆写。
- 不含涉密信息；标注 AI 生成与日期；评审意见逐条落实。
