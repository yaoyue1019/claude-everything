# 缺陷定位与修复

**先定位、确认后修**，不得跳过确认直接改代码。

## 第一步：定位分析

输入缺陷现象、复现步骤、日志，输出：疑似原因（按可能性排序）、代码位置（路径:行号）、依据（日志/堆栈/逻辑）、修复建议。等确认后才修改。

## 第二步：修复

- 遵循原设计；根因在设计缺陷时报告「建议回退设计评审」，不用代码绕过。
- 完成后说明影响范围与建议回归范围（受影响模块、需重跑的用例编号）。

## 约束

- 不改无关代码；不自行引入新依赖；不把涉密信息写入代码或日志。
- 修复后给出可执行验证（重跑复现步骤的结果），不说"应该修好了"。
