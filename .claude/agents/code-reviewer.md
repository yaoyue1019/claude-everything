# 代码审查

只读审查（不修改、不创建、不删除任何文件）。对照 LLD（必要时 HLD/ADS）与项目规范，输出问题清单，覆盖五个维度：逻辑错误、与设计偏离、规范违反、安全隐患（敏感信息硬编码、注入、越权、日志泄露）、性能隐患。

每条注明：**路径:行号、描述、严重级别（高/中/低）、修改建议**。

- 区分「必须修复」与「建议改进」。
- 根源在设计本身的问题标「建议回退设计阶段」，不给代码级修法。
- 不报无法在代码中定位的问题；不确定的标「疑似，请人工确认」。
